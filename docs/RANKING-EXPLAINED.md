# Milla 信息流排序与质量分级算法 · 通俗讲解

> 写给"想搞懂 Milla 为什么这样排"的你，以及未来想改进这套算法的自己。
> 读完你应该能回答三个问题：**一篇文章凭什么排在这个位置？调某个滑块到底改了什么？
> 以后想加新特性该动哪里？**

## 1. 一句话总纲

Milla 的信息流不是"算法推荐"（它不猜你喜欢什么），而是**一场公平的选稿会议**：
每个订阅源是一位编辑，按你定的规则递交候选稿，主持人（排序器）按综合分排队，
再强制让不同编辑轮流发言。

整条流水线像一个**四级漏斗**：

```
某源今日全部文章 N 篇
      │
      ▼ ① 当日候选（低频源回退到"最新几篇"）
      │
      ▼ ② dailyLimit 每日上限截断        ← 每源可配："你今天最多发 N 篇"
      │
      ▼ ③ sampleSize 出场抽样            ← 每源可配："这一轮你最多派 N 位代表"
      │
      ▼ ④ 交替合并（相邻不同源）          ← 全局规则："轮流发言"
   最终信息流
```

漏斗的前三级在**每个源内部**进行（谁也不许多占坑），最后一级在**源之间**进行（防霸屏）。

## 2. 一篇文章的得分是怎么算出来的

每篇候选文章会得到一个 **0 到 1 之间的综合分**：

```
综合分 = 质量权重 × 质量分 + 新鲜度权重 × 新鲜度分
         （默认 0.6）                （默认 0.4）
```

### 2.1 质量分 q：你给源打的"星级"

- 它**属于订阅源，不属于文章**——你在设置里给"少数派"打 0.85 星，
  那么少数派的所有文章都带着 0.85 的质量分出场。
- 这是一个**信任度**概念：你越信任这个源，它就越容易排到前面。
- 默认给的值：少数派 0.85，虎嗅/联合早报 0.8，知乎日报 0.75。

### 2.2 新鲜度分 r：按"年龄"打折扣

用**半衰期**模型（默认 24 小时）：每过一个半衰期，新鲜度就衰减一半。

| 发布时间 | 新鲜度分（半衰期=24h） |
|---|---|
| 刚刚 | 1.00 |
| 1 小时前 | ≈ 0.97 |
| 6 小时前 | ≈ 0.84 |
| 12 小时前 | ≈ 0.71 |
| 24 小时前 | 0.50 |
| 2 天前 | 0.25 |
| 1 周前 | ≈ 0.06 |
| 没有日期的 | 固定 0.25（`missingDateRecency`） |

> 为什么用半衰期而不是线性衰减？因为新闻价值的流失更像放射性衰变——
> 前 24 小时掉得快，之后趋于平缓，"一周前的文章"和"八天前的文章"对你来说差别不大了。
> 线性衰减会让一周前的文章直接归零，低频更新的源（比如周报）就永远没有出场机会。

### 2.3 一个完整演算例子

虎嗅（q=0.8）有一篇 6 小时前发布的文章（r≈0.84）：

```
综合分 = 0.6 × 0.8 + 0.4 × 0.84 = 0.48 + 0.34 = 0.82
```

知乎日报（q=0.75）有一篇 3 天前的文章（r≈0.125）：

```
综合分 = 0.6 × 0.75 + 0.4 × 0.125 = 0.45 + 0.05 = 0.50
```

前者胜出。直觉验证：**高质量的旧文章 和 低质量的新文章，谁赢取决于你把权重滑块拨向哪边**——
这正是你表达"口味"的地方。

## 3. 两个权重与半衰期：你的三个"口味旋钮"

全部在 设置 → 排序参数，改完立即生效。

| 旋钮 | 默认值 | 调大意味着 | 调小的副作用 |
|---|---|---|---|
| 质量权重 | 0.6 | 头部更稳定，"大源"常驻前排 | 新文章可能被压住，时效感变差 |
| 新鲜度权重 | 0.4 | 信息流更像"最新消息流" | 低质量源的新文容易冲到前面 |
| 半衰期 | 24h | 旧文章衰减得慢，整体更"沉稳" | 信息流翻脸快，一小时的旧文就掉队 |

两个权重会在排序前**自动归一化**，所以你只需关心相对比例（0.6/0.4 和 0.75/0.5 效果一样）。

---

## 4. 每源三参数：给每个编辑定"规矩"

| 参数 | 含义 | 什么时候调 |
|---|---|---|
| `dailyLimit` 每日上限 | 该源**参与竞争**的文章每天最多 N 篇（0 = 不限） | 源更新太猛（如知乎日报一天 50 篇），怕它挤占别人的坑 |
| `sampleSize` 出场条数 | 每轮刷新该源最多**派出 N 篇**进入最终信息流 | 想控制某个源在首页的存在感 |
| `qualityScore` 质量星级 | 上面说的信任度 0~1 | 觉得某源内容水/内容好 |

注意区分：`dailyLimit` 管的是"**入池资格**"（按时间倒序截断），`sampleSize` 管的是
"**最终出场**"（按综合分挑）。一个先按时间筛，一个再按分数挑。

## 5. 抽样的两种模式：稳定版 vs 惊喜版

设置里的"随机抽样"开关决定第③级漏斗怎么挑人：

**确定性 Top-K（默认，关闭随机）**
每源按综合分从高到低直接取前 N 篇。同样的数据永远得到同样的信息流——
便于你理解"为什么它排这"，也便于回归测试。

**加权随机（打开随机）**
分数越高被抽中概率越大，但低分者也有机会。用的是
Efraimidis–Spiliotidis 加权随机抽样算法（等价于"给每篇文章按分数加权掷骰子"），
并可用固定随机种子——**随机但可复现**，关掉重开 App 不会乱跳。

> 什么时候开随机？源多、内容同质化、觉得首页"每天都长一样"的时候。

## 6. 交替合并：为什么相邻两条永远不同源

抽完样后，每个源手里都有一小队按分数排好的代表。合并器像一个主持人：

```
循环：
  1. 排除"上一个刚发言的源"
  2. 在剩下的源里，看谁队首的综合分最高，让它发言
  3. 重复，直到所有人都发完言
```

效果：假设虎嗅有 5 篇高分文章，最终流也是 `虎嗅、X、虎嗅、Y、虎嗅…`，
绝不出现 `虎嗅、虎嗅、虎嗅`。只有当别的源都没货了，才允许同一源连续出场。

这就是"多源报纸感"的来源——**每个源都有保底曝光，头部源也垄断不了版面**。

## 7. App 层规则：只增不换的时间线

算法每次只处理"一批候选"，而 App 在算法之上定了**时间线宪法**（`HomeViewModel`）：

1. **首批**：App 第一次启动时，把当时库里的全部文章当作第一批，排序 + 抽样一次，
   得到的顺序**永久固定**（存进 UserDefaults）。
2. **以后每次刷新**：只有"本次新抓到的文章"（不在已见池里的）才走一遍上面的漏斗，
   排好序**整体插到最顶上**；旧文章一个都不动、不删、不重排。
3. **已见池**（seen pool）：首批抽样没被选中的文章也记入池子，
   以后不会突然冒充"新文章"顶到你面前。
4. 已读（变灰）和收藏与顺序无关，独立记录。

> 为什么要这样设计？因为"刷新后整个列表突然重排/消失"是信息流产品最招人恨的行为。
> 代价是：**改权重滑块不会重排现有内容，只对以后的新文章生效**——
> 想看到新规则全面生效，需要等几轮刷新积累新文章。

## 8. 想要什么效果 → 动哪个参数（速查）

| 症状 / 期望 | 处方 |
|---|---|
| 某个源总霸屏 | 降它的 `sampleSize` 或 `dailyLimit`，或降星级 |
| 某个好源总看不到 | 升星级、升 `sampleSize`；确认没有设过小的 `dailyLimit` |
| 首页太"旧"，想看新鲜的 | 新鲜度权重调大，或半衰期调短（如 12h） |
| 首页太"水"，想看出处可靠的 | 质量权重调大 |
| 周报类低频源彻底消失 | 检查 `dailyLimit` 是否为 0 之外的小值（有"最新兜底"，但上限太小仍会挤掉它） |
| 每天打开都一样，想换换口味 | 打开随机抽样 |
| 想让规则立刻"全面生效" | 目前只能等新文章；或删除重装 App 重置时间线（会清掉订阅配置，慎用） |

## 9. 后续改进方向（给未来的自己）

按投入产出比排序，每条注明改动落点：

1. **点击反馈学习（个性化质量分）**
   现状：质量分是静态星级。改进：记录每源/每分类的打开率，动态微调 `qualityScore`
   （如 `q' = 0.9q + 0.1·近期打开率`，带上下限防漂移）。
   落点：`FeedRepository` 加打开计数 → `HomeViewModel` 组装 `FeedSource` 时注入。

2. **负反馈：屏蔽词 / 静音某源一段时间**
   落点：`FeedRankingService.rank` 入口前过滤，或 `RankingConfiguration` 加 `blockedKeywords`；
   UI 放设置页。

3. **"稍后读"与置顶**
   让用户手动把某篇钉在顶部。落点：`HomeViewModel` 的顺序表支持手动插入；
   与收藏列表一起做。

4. **去重升级：相似文章合并**
   同一篇新闻被多个源转载时，保留得分最高者，其余折叠为"另有 N 家报道"。
   落点：`StableIdentifier` 之外加标题相似度（编辑距离/jaccard）预处理，
   在漏斗第②级之后做跨源去重。

5. **半衰期按源个性化**
   快讯源（联合早报）用短半衰期，深度源（少数派）用长半衰期。
   落点：`FeedSource` 加可选 `halfLifeOverride`，`recencyScore` 按 item 所属源取值。

6. **全天节奏感知**
   早晨偏新闻、夜里偏深度长文（按时段切换权重预设）。落点：`AppSettings` 加预设组，
   `HomeViewModel` 按 `Calendar.current.hour` 选择配置。

7. **多样性指标与防单调**
   除"相邻不同源"外，再加"每 6 条内每个启用的源至少出现 1 次"的硬约束。
   落点：`FeedRankingService.interleave`。

> 改动原则：**算法改动必须落在 MillaCore**（跨平台可测），先用 XCTest 固化期望行为，
> 再改实现；`milla-cli rank Fixtures` 是最方便的端到端观察窗口。

## 10. 一页备忘

```
漏斗：当日候选 → dailyLimit → sampleSize(打分抽样) → 交替合并
打分：score = wQ·q + wR·r     q=源星级(静态)  r=0.5^(年龄/半衰期)
默认：wQ=0.6  wR=0.4  半衰期=24h  无日期 r=0.25
抽样：默认确定性 Top-K；可选加权随机（带种子，可复现）
合并：贪心交替，相邻不同源
时间线：只增不换；排序只作用于新批次；顺序持久化；已见池防"伪新文章"
```
